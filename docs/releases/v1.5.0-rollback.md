## Restore one existing installation

The 1.5 installer and Debian package preserve `/etc/muonfp.conf` and log data.
To roll back only the executable:

1. Stop the service: `sudo systemctl stop muonfp`.
2. Download and extract `muonfp_DEB_1.4.RC5.tar.gz` from the preserved release.
3. Back up the 1.5 executable.
4. Install the RC binary as `/usr/local/bin/muonfp` with mode `0755`.
5. Confirm the existing configuration is compatible and restart the service.

The RC artifact is amd64 Linux only. Keep the backed-up 1.5 executable until
the service and fingerprint output have been verified.

## Repository rollback after publication

Prefer a revert commit over rewriting `main` or deleting published history:

1. Identify the merge commit that introduced the 1.5 release changes.
2. Create a rollback branch from the current `main`.
3. Run `git revert <release-merge-commit>`.
4. Run the complete CI and Debian package validation suite.
5. Merge the rollback PR and publish a patch release explaining the rollback.

If only release metadata or an artifact is wrong, leave source history intact,
draft a corrected release, rebuild from the `v1.5.0` tag, and replace it with a
new patch version such as `v1.5.1`.
